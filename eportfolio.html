What is Full Stack Development?

When I first heard the phrase "full stack developer" I assumed it just meant someone who was good at everything — which felt a bit vague. After studying it properly I have a much better understanding of what it actually refers to.

A full stack developer is someone who can work across every layer of a web application — from the part the user sees (the front end) all the way through to the server, the application logic, and the database (the back end). The word "stack" refers to the set of technologies stacked on top of each other to make the application function.

The "stack" is not just a metaphor — it literally describes how different layers of a system sit on top of each other, each relying on the layer beneath it.

A common way to visualise this is through a diagram. The diagram below shows the four main layers and the kinds of technologies that typically sit in each one:

FRONT END  ·  HTML · CSS · JavaScript · Bootstrap

What the user sees and interacts with in their browser.

SERVER LOGIC  ·  Node.js · Python · PHP · Ruby

Handles requests from the browser and applies business logic.

APIs & SERVICES  ·  REST · GraphQL · Authentication

Connects front end to data and third-party services.

DATABASE  ·  MySQL · MongoDB · PostgreSQL

Stores and retrieves the application's data persistently.

Understanding all of these layers is what makes someone a full stack developer. In practice, many developers tend to specialise more heavily on one side — some are naturally more comfortable in the browser (front-end focused), others prefer working with databases and server logic (back-end focused). Being able to move between both, even if not an expert at every layer, is the defining trait.

On this module so far we have focused primarily on the front-end layer — HTML, CSS, Bootstrap, and JavaScript — which are the core building blocks of anything a user actually sees. These sit at the top of the stack and are the entry point for most developers learning web development.

One thing I found useful when thinking about this was the idea that the front end and back end are always communicating. When you type a URL into a browser, the front end sends a request, the server processes it, possibly queries a database, and then sends a response back that the browser renders. All of that happens in fractions of a second.

// 02

HTML

HTML — HyperText Markup Language — is the backbone of every web page. It is not a programming language (it cannot perform logic or calculations), but a markup language that describes the structure and content of a document using elements wrapped in tags.

The browser reads the HTML file and builds a Document Object Model (DOM) — a tree-like representation of the page that CSS and JavaScript can then interact with. Without HTML there is nothing for the other layers to attach to.

Basic Page Structure

Every HTML document follows the same basic skeleton. I have found it helpful to memorise this early on because all pages, however complex, are built on top of it: 

<!-- Every HTML page starts with a DOCTYPE declaration -->
<!DOCTYPE html>
<html lang="en">

  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My Web Page</title>
  </head>

  <body>
    <h1>Hello, World!</h1>
    <p>This is a paragraph of text.</p>
  </body>

</html>

The <head> contains metadata — information about the page, like its title and character encoding. The <body> contains everything the user actually sees.

Semantic HTML

One of the most important things I have learned about HTML is the idea of semantic elements. Rather than wrapping everything in generic <div> tags, HTML5 introduced elements like <header>, <nav>, <main>, <article>, and <footer>. These tell the browser — and screen readers — what each part of the page is for, not just how it looks. This matters for accessibility and for SEO. 

<header>
  <nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
  </nav>
</header>

<main>
  <article>
    <h1>Article Title</h1>
    <p>Content goes here...</p>
  </article>
</main>

<footer>
  <p>© 2024 My Website</p>
</footer>

CSS

CSS — Cascading Style Sheets — is what transforms a plain HTML document into something that actually looks designed. It controls everything visual: colours, fonts, spacing, layout, animations, and how a page responds to different screen sizes.

The word cascading is the important bit. CSS rules flow downward through the document, and more specific selectors override more general ones. Understanding specificity took me a while — I initially found it confusing when a style I had written wasn't applying, and it usually turned out to be a specificity issue.

How CSS is Applied

/* Targeting an element directly */
h1 {
  color: #1a1a1a;
  font-size: 2rem;
}

/* Targeting a class */
.card {
  background: #ffffff;
  border-radius: 8px;
  padding: 1.5rem;
  box-shadow: 0 2px 12px rgba(0,0,0,0.08);
}

/* Pseudo-class — applies only on hover */
.card:hover {
  transform: translateY(-4px);
  transition: transform 0.2s ease;
}

Responsive Design with Media Queries

One of the most practical things CSS can do is make a layout adapt to different screen sizes using media queries. This is essential for modern web development because users access sites on everything from a small phone screen to a widescreen monitor. 

/* Default styles for small screens (mobile-first) */
.container {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

/* At 768px and above, switch to a horizontal layout */
@media (min-width: 768px) {
  .container {
    flex-direction: row;
  }
}

I have found the mobile-first approach makes the most sense once you get used to it — you write the simplest styles first (for small screens) and then layer complexity on for larger ones. This also tends to produce leaner CSS overall.

// 04

Bootstrap Framework

Bootstrap is an open-source CSS framework that provides a collection of pre-built components and a responsive grid system. Rather than writing layout and component styles from scratch every time, Bootstrap lets you apply ready-made classes to your HTML.

The core of Bootstrap's layout system is its 12-column grid. You define rows and then specify how many columns each element should span at different breakpoints. The breakpoints (sm, md, lg, xl) correspond to screen widths, making it straightforward to create responsive layouts without writing any custom media queries.

The Grid System

<!-- A three-column layout that stacks on mobile -->
<div class="container">
  <div class="row g-3">
    <div class="col-12 col-md-4">Column 1</div>
    <div class="col-12 col-md-4">Column 2</div>
    <div class="col-12 col-md-4">Column 3</div>
  </div>
</div>

Notice col-12 col-md-4 — on small screens each column takes up all 12 columns (full width), and from the md breakpoint upwards it takes up 4 (one third of 12). That is responsive layout with a single class.

JavaScript

JavaScript is the only programming language that runs natively in the browser. Where HTML defines structure and CSS defines appearance, JavaScript adds behaviour — the ability to respond to user interactions, manipulate the DOM, fetch data from servers, and create dynamic experiences without reloading the page.

Unlike HTML and CSS, JavaScript is a proper programming language with variables, functions, loops, conditionals, and data structures. It can feel like a big jump at first, but once the core concepts click the rest starts to follow.

Fundamentals — Variables, Functions, Events

// Variables (prefer let and const over var)
const userName = "Alex";
let clickCount = 0;

// A simple function
function greet(name) {
  return `Hello, ${name}!`;
}

// Selecting a DOM element and listening for events
const btn = document.querySelector("#myButton");

btn.addEventListener("click", () => {
  clickCount++;
  console.log(`Clicked ${clickCount} times`);
});

The key concept above is the event listener — JavaScript waits for something to happen (a click, a keypress, a form submission) and then executes a function in response. This is called event-driven programming and it's fundamental to how interactive web pages work.

DOM Manipulation

The DOM (Document Object Model) is what JavaScript uses to interact with an HTML page. It represents the page as a tree of objects, and JavaScript can read or change any part of it in real time. 

// Get a reference to an element
const heading = document.getElementById("main-heading");

// Change its text content
heading.textContent = "Updated by JavaScript!";

// Create a new element and add it to the page
const newPara = document.createElement("p");
newPara.textContent = "This paragraph was created dynamically.";
document.body.appendChild(newPara);

// Toggle a class
heading.classList.toggle("active");
